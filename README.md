# 핀로그 (PinLog)

## 2026-09 기록 중심 개편

메인은 **나의 기록 / 돌아보기 / 작은 작업실**로 나뉩니다. 오늘의 기록이 기본이며 전체 기간, 날짜 선택, 본문·상세·태그 검색을 지원합니다. 돌아보기는 실제 최근 7일 기록을 집계합니다. 시계·캐릭터는 작업실로 이동했고 미니 위젯과 기존 데이터 형식은 유지합니다.

- 종이색·세이지 그린, 읽기 중심 카드, 모바일 하단 메뉴, 다크 모드.
- 저장 성공 후 빠른 기록 알림. 직접 입력은 저장 실패 시 초안을 보존하고 오류 안내.
- 광고는 토스의 선택형 꾸미기 보상에 한정. 기록·검색·회고·내보내기는 광고 없이 이용.
- 상점 또는 구매 미리보기에서 광고를 준비하며 기본 꾸미기를 열 때는 광고를 준비하지 않음.
- 하루 최대 **3회**, 기본 **10 리워드/회**. 소품 **10**, 모자 **20**, 캐릭터·의상 **30**. 기존 잔액·보유 아이템 유지.
- 지급은 SDK의 `userEarnedReward`에만 연결. 실제 수량은 콘솔 설정을 따르므로 출시 콘솔에서도 10으로 설정해야 화면 안내와 일치함.
- 수익 개선은 가설이며 실측하지 않았음. 출시 후 기록 다음 날 재방문율, 작업실 방문율, 자발적 광고 완료율, 광고 후 이탈률을 함께 비교할 것. 개인 기록 본문을 광고 분석에 보내지 않음.
- `npm run check:journal`: 격리된 저장소로 검색·날짜·저장·재실행·회고·320–1280px·다크 모드 확인 및 `design/journal-preview/` 캡처.
- `npm run check:rewards`: 가짜 SDK로 지급·중복 방지·구매·재실행·일일 한도 확인. 운영 광고 호출 없음.

아래 기존 설명 중 메인 화면의 배치 설명은 개편 전 구조입니다. 현재 화면 구성은 위 내용을 기준으로 봅니다.


화면 구석에 띄워두고 쓰는 미니 위젯형 타임 트래커 & 일기장.

- **미니 모드** — 프레임리스 · 투명 · Always-on-top 플로팅 위젯. 드래그로 자유 이동.
- **메인 모드** — 타임라인 조회/수정, 통계, CSV·클립보드 내보내기.
- **듀얼 테마** — 아날로그 시계(클릭해서 핀) ↔ 디지털 시계(`+` FAB).

## 실행

```bash
npm install
npm run dev
```

앱은 **미니 위젯으로 시작**합니다. 위젯 위에 마우스를 올리면 컨트롤 바(뷰 전환 / `⤢` 펼치기 / `✕` 닫기)가 나타납니다.

| 명령 | 설명 |
| --- | --- |
| `npm run dev` | 데스크탑 개발 모드 (HMR) |
| `npm run build` | 타입체크 + 3개 번들(main/preload/renderer) 빌드 |
| `npm run build:mac` / `build:win` | 설치 파일 패키징 |
| `npm run build:web` | 웹사이트(PWA) 빌드 → `dist-web/` · [배포 방법](#github-pages-로-배포하기) |
| `npm run check:ui` | 드래그 영역 + 입력 창 + 입력 플로우 회귀 검사 (창 없이 실행) |
| `npm run check:rewards` | 토스 번들을 가짜 SDK 로 빌드해 광고 리워드 → 구매 전체 흐름 검사 |
| `npm run check:e2e` | 실제 앱을 띄워 위젯 클릭 → 입력 창 → 저장 전체 경로 검사 |

## 디렉토리 구조

Electron의 3-프로세스 경계를 **디렉토리로 그대로 드러내는** 구조입니다. 경계가 흐려지면 보안 설정(`contextIsolation`)이 슬금슬금 무너지기 때문입니다.

```
src/
├── shared/              ← 세 프로세스가 공유. Node/DOM API를 절대 쓰지 않는다
│   └── types.ts            Pin 스키마, IPC 채널 상수, 미니창 크기표
│
├── main/                ← Node 권한을 가진 메인 프로세스
│   ├── index.ts            앱 수명주기, 단일 인스턴스 락, 전역 단축키
│   ├── windows.ts          ★ 창 생성 로직 (프레임리스/투명/always-on-top)
│   ├── store.ts            데이터의 단일 소유자. userData/pins.json 원자적 쓰기
│   └── ipc.ts              IPC 핸들러 + 창 간 브로드캐스트
│
├── preload/
│   └── index.ts         ← 유일한 특권 통로. contextBridge 로 window.pinlog 노출
│
└── renderer/            ← 권한 없는 순수 웹 앱
    ├── index.html
    └── src/
        ├── App.tsx              ?window= 로 미니/메인 분기
        ├── store/usePinStore.ts Zustand 스토어
        ├── lib/
        │   ├── bridge.ts        ★ 플랫폼 추상화 (Electron ↔ 웹 폴백)
        │   ├── time.ts          시계 각도 계산, 포맷
        │   └── export.ts        CSV / 마크다운 변환
        └── components/
            ├── MiniView.tsx     미니 모드 레이아웃
            ├── MainView.tsx     메인 모드 레이아웃
            ├── AnalogClock.tsx  SVG 시계 + 다이얼 핀 마커
            ├── DigitalClock.tsx 디지털 시계 + [+] FAB
            ├── ViewToggle.tsx   아날로그 ↔ 디지털
            ├── PinComposer.tsx  입력 팝업 (프리셋 / 집중 토글)
            └── Timeline.tsx     타임라인 리스트
```

### 핵심 설계 결정 3가지

**1. 창은 둘, 렌더러 번들은 하나.**
`index.html?window=mini` 처럼 쿼리스트링으로 분기합니다. 번들이 갈라지면 컴포넌트가 중복되고, 미니/메인이 서서히 다른 앱이 되어버립니다.

**2. 데이터의 주인은 메인 프로세스다.**
창이 두 개 뜨는 앱에서 렌더러의 `localStorage`를 쓰면 두 창의 상태가 갈라집니다. 메인이 `pins.json`을 소유하고, 변경이 생기면 `pins:changed` 로 모든 창에 밀어줍니다 (`src/main/ipc.ts`의 `broadcast()`). 그래서 미니에서 찍은 핀이 메인 타임라인에 즉시 나타납니다.

**3. 네이티브 접근은 `lib/bridge.ts` 한 곳으로 격리.**
컴포넌트는 `PinLogBridge` 인터페이스만 압니다. `window.pinlog`이 없으면(=브라우저) localStorage 폴백이 자동으로 쓰이므로, **같은 코드가 PWA로도 돕니다**. Tauri로 갈아탈 때도 이 파일의 구현체만 교체하면 됩니다.

## 미니 모드 창의 핵심 설정

`src/main/windows.ts`의 `createMiniWindow()`. 이 조합이 위젯의 전부입니다.

```ts
const win = new BrowserWindow({
  frame: false,        // OS 타이틀바 제거
  transparent: true,   // 배경 투명 → 렌더러가 그린 둥근 시계만 보임
  hasShadow: false,    // 투명 창에 사각 그림자가 남는 것 방지
  resizable: false,    // 위젯은 고정 크기
  alwaysOnTop: true,
  skipTaskbar: true,   // 작업표시줄/Dock 목록에서 숨김
  backgroundColor: '#00000000',
})
win.setAlwaysOnTop(true, 'screen-saver')                       // 전체화면 앱 위에도
win.setVisibleOnAllWorkspaces(true, { visibleOnFullScreen: true })  // Space 이동해도 따라옴
```

### 드래그 이동 — 여기서 대부분 막힙니다

CSS `-webkit-app-region: drag`을 준 영역을 누르고 끌면 창이 따라옵니다 (`src/renderer/src/index.css`의 `.drag-region`).

**함정 1: 드래그 영역 안의 버튼·입력은 클릭이 먹지 않습니다.** 반드시 `.no-drag`를 줘야 합니다.

**함정 2 (훨씬 안 보이는 함정): `.no-drag`는 DOM 순서에 따라 무효화됩니다.**
Electron은 요소를 트리 순서대로 훑으며 `drag`는 합집합(union), `no-drag`는 차집합(difference)을 **순차 적용**합니다. 그래서 `.no-drag` 요소가 그것과 겹치는 `.drag-region`보다 **앞에** 오면, 뒤에 오는 drag의 사각 바운딩 박스가 그 영역을 다시 덮어써서 클릭이 창 드래그로 먹힙니다. 화면상으로는 z-index 덕에 버튼이 멀쩡히 위에 보이기 때문에 원인을 찾기 어렵습니다.

> 규칙: **겹치는 `.no-drag`는 항상 `.drag-region` 뒤에 배치할 것.** (조상-자손 관계는 자손이 자연히 뒤에 오므로 안전합니다.)

`npm run check:ui`가 이걸 자동으로 잡습니다 — 위젯의 모든 drag/no-drag 요소 쌍을 검사하고, 일부러 옛 순서로 되돌린 **음성 대조군**까지 돌려서 검사 자체가 살아있는지 확인합니다. 아날로그 위젯은 이 충돌을 다음과 같이 해결했습니다:

| 영역 | 속성 | 동작 |
| --- | --- | --- |
| 바깥 테두리 (눈금·마커 링) | `.drag-region` | 창 이동 |
| 안쪽 원 (62%) | `.no-drag` | 클릭 → 핀 생성 |
| 마커 히트박스 | `.no-drag` | 클릭 → 해당 핀 수정 |

SVG는 `pointer-events-none`으로 꺼서 순수 장식으로 두었습니다. 마커 위에서도 드래그가 끊기지 않게 하기 위함입니다.

또 하나: 뷰를 전환하면 위젯 모양이 바뀌므로(원형 220×220 ↔ 가로 바 280×132) 창 크기도 함께 바꿔야 합니다. `resizeMini()`는 **우측 상단을 기준점으로 고정**해서, 화면 오른쪽 구석에 붙여둔 위젯이 크기 변경 때 튀지 않게 합니다.

## 입력은 왜 별도의 창인가

입력 UI 를 미니 창 '안'에 모달로 그리면 **220px 위젯 안에서 잘립니다.** 팝업은 500px가 넘으니까요.

처음에는 팝업이 열릴 때만 미니 창을 키웠다가 되돌리는 방식을 썼는데, 이건 **투명 창 리사이즈에 의존**합니다. Electron 문서가 이를 보장하지 않습니다 — *"Transparent windows are not resizable."* macOS 에서는 동작했지만 Windows/Linux 에서 깨질 수 있고, 위젯이 화면 가장자리에 있으면 커진 창이 밀려납니다.

그래서 입력은 **처음부터 제 크기(`COMPOSER_SIZE` 380×620)로 뜨는 독립 창**으로 분리했습니다 (`createComposerWindow()` in `windows.ts`). 이 구조의 이점:

- 위젯 크기와 완전히 무관 — 위젯이 220px든 얼마든 입력창은 항상 온전합니다.
- 리사이즈를 아예 하지 않으므로 플랫폼 제약을 피합니다.
- 위젯이 있는 디스플레이 중앙에 뜨고, 작업 영역 안으로 클램프됩니다.

초기값(기록 시각 / 수정할 핀 id)은 **쿼리스트링으로** 넘깁니다 — 별도의 상태 동기화 IPC 가 필요 없습니다.

```
?window=composer&ts=1786952288657&id=<pin-id>
```

프레임리스라 헤더가 창을 옮기는 유일한 손잡이입니다(`drag-region`). 저장하거나 Esc 를 누르면 창이 닫히고 포커스가 위젯으로 돌아갑니다. 웹/PWA 에는 창 개념이 없으므로 기존 인라인 모달로 폴백합니다(`PinComposer`의 `standalone` prop).

그래도 좁은 화면에서 안전하도록 카드는 스크롤 가능하고, **저장 버튼은 `sticky bottom-0`** 으로 항상 보이게 고정했습니다.

## 입력 방법 (세 가지를 섞어 쓸 수 있음)

| 방법 | 설명 |
| --- | --- |
| **직접 입력** | 자유 텍스트. 일기처럼 길게 써도 됩니다. Enter 저장 / Shift+Enter 줄바꿈 / Esc 취소 |
| **빠른 입력** | 업무·회의·휴식·개인공부 프리셋 원클릭 |
| **태그 직접 추가** | 프리셋에 없는 태그를 손으로. Enter 또는 쉼표로 확정, 태그 클릭하면 제거 |
| **시각 수정** | 팝업 좌상단 시간 필드로 기록 시각을 수기 조정 |

프리셋을 눌러도 **직접 쓴 글은 덮어쓰지 않습니다.** 비어 있거나 다른 프리셋 라벨만 들어있을 때만 갈아끼웁니다.

### 플랫폼 주의사항

- **Windows**: `transparent: true` + `resizable: true` 조합은 창 테두리에 아티팩트가 생깁니다. 미니 창을 `resizable: false`로 둔 이유입니다.
- **Linux**: 투명 창은 컴포지터에 의존합니다. 일부 환경에서 배경이 검게 나오면 `transparent`를 끄고 불투명 라운드 배경으로 폴백하세요.
- **macOS**: 메인 창은 `titleBarStyle: 'hiddenInset'`이라 헤더 왼쪽에 신호등 버튼 자리(`pl-20`)를 비워두었습니다.

## 앱인토스 (미니앱)

```bash
npm run dev:toss      # 미니앱 개발 서버
npm run ait:test      # 테스트 광고로 빌드 → pinlog.ait  (토스 앱에서 테스트할 때)
npm run ait:release   # 운영 광고로 빌드 → pinlog.ait  (검토 요청·출시할 때)
```

`ait:*` 는 `build:toss`(또는 `build:toss:release`) 로 `dist/` 를 만든 뒤 `ait build` 로 포장한다.

### 세 갈래 빌드

| 대상 | 설정 | 출력 | 저장소 |
| --- | --- | --- | --- |
| 데스크탑 | `electron.vite.config.ts` | `out/` | 메인 프로세스 `pins.json` |
| PWA | `vite.web.config.ts` | `dist-web/` | `localStorage` |

`__TOSS_BUILD__` 상수로 갈린다. PWA·데스크탑 빌드에서는 `false` 로 치환돼
토스 SDK 와 어댑터가 통째로 제거되고, 반대로 토스 번들에는 서비스워커·manifest 가 들어가지 않는다.
(`npm run build:web` 후 `grep TossAds dist-web/assets/*.js` 로 확인 가능)

### 왜 localStorage 를 안 쓰는가

미니앱은 토스 앱의 WebView 안에서 돈다. WebView 저장소는 앱이 캐시를 정리하면 같이 날아갈 수 있다 —
**일기 앱에서는 치명적**이다. 그래서 토스 빌드는 SDK 의 `Storage`(앱이 종료돼도 유지되는 네이티브 저장소)를 쓴다.
기존 `localStorage` 기록은 첫 실행 때 자동으로 옮긴다 (`migrateFromLocalStorage`).

> ⚠️ 그래도 **기기 안에만** 있다. 앱 삭제·기기 변경이면 사라진다.
> 진짜 해결은 토스 로그인 + 서버 저장인데, 그건 **사업자등록이 필요**하다.

| 토스 뒤로가기와 자체 뒤로가기 중복 금지 | 자체 뒤로가기 없음. `graniteEvent.backEvent` 하나로 처리 — 입력 시트가 열려 있으면 시트만 닫고, 아니면 `Screen.close()` |

### 광고 리워드 상점

꾸미기 화면에서 **광고를 끝까지 보면 리워드**를 받고, 리워드로 **동물 캐릭터 · 프리미엄 옷 · 모자 · 소품**을 삽니다.
광고가 있는 앱인토스에서만 보입니다 — 데스크탑·웹에는 상점 탭·캐릭터 탭·광고 버튼·상점 아이템이 전부 빠집니다.

| 코드 | 역할 |

| `lib/rewardAd.ts` | 보상형 광고 한 칸: `load → show → 다음 load`. SDK 를 주입받아 토스 밖에서도 검사 가능 |

**가격표** (광고 1회 = 리워드 10, 하루 3회)

#### ⚠️ 테스트 광고 ID vs 운영 광고 ID

앱인토스 문서: **개발 중 운영 광고 ID 로 테스트하면 정책 위반으로 제재**받을 수 있다.
그래서 운영 ID(`ait.v2.live.9684c2e6e5dc4aa1`)는 **두 조건이 모두 맞을 때만** 쓴다.

1. `npm run ait:release` 로 빌드했다 (`__TOSS_ADS_LIVE__`)
2. 진짜 토스 앱 안이다 (`Environment.environment === 'toss'`, 샌드박스 앱 아님)

나머지는 전부 테스트 ID(`ait-ad-test-rewarded-id`)이고, 꾸미기 화면 광고 버튼 아래에 **`테스트 광고`** 표시가 붙는다.
일반 빌드(`ait:test`)에는 운영 ID 문자열 자체가 번들에 들어가지 않는다.

- 광고 흐름(받기·닫기·실패)을 확인할 때는 **`ait:test` 번들**을 올려 토스 앱에서 테스트한다.
- 출시용 번들(`ait:release`)은 토스 앱 테스트에서 **광고 버튼을 누르지 않는다.**
  SDK 에는 '검토 중인 번들인지' 알려주는 값이 없어서, 이 번들은 토스 앱에서 열리는 순간 운영 광고를 쓴다
  (꾸미기 화면을 열면 미리 불러오기까지 한다).
- 출시한 뒤 버튼 아래에 `테스트 광고` 가 보이면 `ait:test` 번들을 올린 것 — 수익이 나지 않는다.

#### 콘솔 설정과 맞춰야 하는 것

광고 그룹의 **보상 이름·수량은 사용자에게 그대로 보이고, 앱에서 실제로 주는 것과 같아야 한다** (광고 정책).

- 서비스 내 보상 단위: **리워드** (`REWARD_NAME`)
- 수량: **10** (`DEFAULT_REWARD`) — 버튼 문구 '광고 보고 리워드 10 받기' 와 가격표가 이 단위다
- 실제 적립은 SDK 가 넘겨주는 수량(= 콘솔 값)을 쓰고, 비어 오면 10. 콘솔 수량을 바꾸면 두 상수도 같이 바꾼다.

#### 지키는 것 (`scripts/check-rewards.js`)

- 보상은 `userEarnedReward` 에서만, 그 순간 저장한다. 닫기(`dismissed`)만으로는 주지 않는다
- 한 광고에서 보상 이벤트가 두 번 와도 한 번만 준다
- 닫힘 이벤트가 끝내 안 오면 60초 뒤 버튼을 풀어 준다 (보상은 이미 들어가 있다)
- **지갑을 못 읽으면 상점을 숨긴다.** 빈 지갑으로 시작하면 다음 저장이 진짜 잔액을 0 으로 덮어쓴다
- 사지 않은 상점 아이템은 입을 수 없다 (화면 + 스토어 두 겹)
- 지갑 저장은 한 줄로 세운다 — 적립과 구매가 겹쳐도 옛 잔액이 나중에 써지지 않게

음성 대조군으로 확인함: '닫기만 해도 보상', '환경 확인 없이 운영 ID', '읽기 실패 시 빈 지갑' 으로 코드를 일부러
망가뜨리면 이 검사가 각각 실패한다.

> 리워드는 기기 안(토스 Storage)에만 있다. 서버 검증이 없으므로 꾸미기 전용이어야 하고,
> 현금성 보상(토스 포인트 등)으로 바꿔주는 데 쓰면 안 된다.

## 데이터 스키마

```ts
interface Pin {
  id: string          // uuid
  timestamp: number   // epoch ms — 다이얼 각도 = (시%12 + 분/60) × 30°
  text: string
  detail?: string     // 상세 메모. 예전 기록에는 없으므로 항상 optional
  tags: string[]      // 프리셋: work / meeting / break / study
  isFocusMode: boolean // '선택과 집중' — 타임라인 뱃지 + 다이얼 마커 강조색
}
```

설정은 `userData/settings.json` 한 파일에 모여 있습니다 (`theme`, `avatar`).

**함정: 이 파일의 소유자는 `src/main/settings.ts` 하나뿐입니다.**
예전에는 `theme.ts`가 `JSON.stringify({ theme })`로 파일을 통째 덮어썼습니다.
설정이 하나일 때는 멀쩡했지만, 두 번째 항목이 생기는 순간 테마를 바꿀 때마다
그 항목이 날아갑니다. 새 설정을 추가할 때는 반드시 `getSetting`/`setSetting`을
거치세요. `scripts/check-settings.js`가 이 회귀를 지킵니다.

## 활동 색

`src/renderer/src/lib/category.ts`. 활동마다 색이 다르고, **같은 활동은 화면
어디서나 같은 색**입니다 — 타임라인 점, 태그 칩, 하루 띠 막대, 시계 마커,
주간 막대, 프리셋 버튼 아이콘, 입력창의 프리셋 칩.

- 프리셋(업무·회의·휴식·개인공부)은 고정 색
- 직접 만든 태그는 **문자열 해시**로 색을 받습니다. 무작위가 아닌 게 중요합니다 —
  같은 태그가 항상 같은 색이어야 색이 정보가 되고, 저장소에 색을 따로 기록할
  필요도 없어집니다
- 태그가 여러 개면 프리셋 태그가 이깁니다 (`#work #회고` → 업무 색)
- 태그가 없으면 중립 회색

실제 색값은 `index.css` 의 `--c-cat-*` 에 있습니다. 여기에 hex 를 두면 다크
모드에서 같은 색을 그대로 써서 탁해집니다.

**집중(--c-focus, 앰버)과 겹치지 않는 색으로 골랐습니다.** 둘이 닮으면 '집중한
기록'인지 '휴식 기록'인지 구별이 안 됩니다. 하루 띠에서도 색은 활동, **길이**는
집중 여부로 나눴습니다 — 둘 다 색으로 표현하면 서로를 지웁니다.

`scripts/check-category.js` 가 지킵니다. 색을 유틸리티 클래스가 아니라 인라인
style 로 칠하므로 타입 검사로는 어긋나도 잡히지 않습니다. 실제로 **계산된**
색을 읽어 화면 여섯 곳이 같은 색을 쓰는지, 다크 모드에서 값이 실제로 바뀌는지
확인합니다.

## 캐릭터 (재미 요소)

기록을 쌓으면 레벨이 오르고 꾸밀 것이 열립니다. `src/renderer/src/lib/avatar.ts`.

**핵심 설계: 레벨과 경험치는 저장하지 않습니다.** 매번 `pins`에서 계산합니다
(`progressOf`). 저장하면 진실이 둘이 되어 — 기록을 지웠는데 레벨은 그대로인 상태가
가능해지고, 저장 파일을 고쳐 레벨을 올릴 수도 있게 됩니다. 저장하는 것은 "무엇을
입고 있는가"(`AvatarLook`)뿐입니다.

- 경험치: 기록 1건 +10, 집중 +5, 상세 메모 +3
- 레벨업 비용: `100 + (레벨-1) × 60` (선형). 만렙 17
- 한 번 연 것은 도로 잠기지 않습니다 (`isUnlocked`가 착용 중인 것도 해금으로 봄) —
  기록을 지웠다고 쓰고 있던 왕관을 빼앗으면 안 됩니다

칸은 열입니다: **캐릭터 · 피부 · 머리 · 머리색 · 안경 · 상의 · 컨셉 · 모자 · 소품 · 배경**.
캐릭터(사람·고양이·강아지)는 앱인토스 상점에서만 보입니다 — 위 '광고 리워드 상점'.

**동물 캐릭터는 사람 몸을 그대로 입습니다.** 머리통과 꼬리만 따로 그리고, 팔레트에서
`S s`(손·목)를 털색으로, `W w`(신발)를 발바닥색으로 덮어씁니다. 그래서 기존 옷·안경·모자·소품이
전부 동물 위에도 맞습니다. 털색이 정해져 있어 피부·머리·머리색 칸은 안내로 바뀝니다.

**컨셉만 성격이 다릅니다.** 모자·소품처럼 얹히는 게 아니라 스프라이트의 몸(11~17줄)을
통째로 갈아끼웁니다. 그래서 `BASE` 를 `HEAD`(0~10줄) + `BODY_DEFAULT`(11~17줄)로
쪼개 두었습니다 — 머리를 건드리지 않으므로 고른 피부색·머리모양·모자가 컨셉을 바꿔도
그대로 남습니다. 컨셉의 몸도 `c`(상의 색)를 그대로 쓰므로 상의 칸이 컨셉 위에서도
계속 의미를 가집니다(정장이면 넥타이 색). 새 컨셉을 추가할 땐 11줄에서 시작하는
7줄짜리 스프라이트만 쓰면 됩니다.

**머리색은 머리 모양과 분리돼 있습니다.** 예전엔 모양마다 색이 박혀 있어서
(단발=갈색, 긴머리=검정 …) "긴머리인데 금발"이 불가능했고, 색 하나 늘릴 때마다
아이템이 모양 수만큼 늘어났습니다. 스프라이트에서 색 글자를 `h` 하나로 빼고
머리색 칸이 채웁니다 — `layersOf` 에서 머리카락만 팔레트를 다르게 넘기는 이유입니다.

**피부색과 타고나는 머리색(검정·갈색·금발)은 전부 레벨 1 입니다.** 다른 칸과 달리 이건 보상이 아니라 '나'이기 때문입니다.
자기 모습을 고르는 데 레벨을 요구하면 어떤 사용자에게는 "너로 보이려면 먼저 자격을
갖춰라"가 됩니다. 색으로 주는 보상은 상의 칸이 맡습니다. 라벨은 인종이 아니라 톤으로
씁니다(밝은/살구/갈색/진한).

### 그림 데이터 — 손으로 고치지 않는다

캐릭터는 **컨셉 01(PINLOG PIXEL AVATAR)** 을 32×40 격자로 옮긴 것입니다.

```
scripts/avatar-art/
├── draw.mjs      타원·사각형·stamp·외곽선 같은 그리기 도구
├── pieces.mjs    ★ 조각 그림 (머리통·몸·머리 7종·안경·모자·소품·배경·자세)

├── generate.mjs  → src/renderer/src/lib/avatarArt.ts 생성 (격자 폭 검사 포함)
└── preview.mjs   전체 아이템 보드 HTML (눈으로 확인용)
```

그림을 고치려면 `pieces.mjs` 를 고치고 **`npm run art`**. `avatarArt.ts` 를 직접 고치면
다음 생성 때 덮어써집니다. 1,000칸 넘는 격자를 손으로 치면 형태가 금방 삐뚤어져서,
큰 형태는 도형으로 잡고 작은 디테일만 stamp 로 찍습니다.

레이어는 뒤에서 앞으로 **배경 → 뒷머리 → 몸(자세·옷 모양) → 머리통 → 앞머리 → 안경 →
모자 → 소품** 입니다. 뒷머리가 몸 뒤에 와야 긴 머리가 어깨 뒤로 넘어갑니다. 머리 위치는
모든 자세에서 같아서 머리카락·안경·모자를 자세마다 다시 그리지 않습니다.

**크기는 40의 정수배로만** 씁니다 — 꾸미기 타일 80, 메인 카드 120, 온보딩 160.
정수배가 아니면 픽셀 폭이 들쭉날쭉해집니다. 예전 16×18 이 46·62px 에서 쓰였던 이유가
이것이고, 새 해상도를 그 크기에 그대로 넣으면 얼굴이 뭉개졌습니다.

### 스프라이트를 고칠 때 지켜야 할 것

- **앞머리 끝은 10줄에서 멈춘다.** 머리카락 외곽선은 얼굴 위에 떨어질 때 머리 그늘색이
  되는데, 11줄까지 내리면 그 한 칸이 눈(12줄) 모서리를 덮어 밝은 머리색일 때 눈에 색이
  묻습니다. `check-avatar` 의 '머리색을 바꿔도 얼굴은 그대로' 가 실제로 이걸 잡았습니다.
- **두 칸 틈을 비우지 않는다.** 양쪽 외곽선이 겹쳐 굵은 검은 막대가 됩니다(다리 사이가
  그랬습니다). 한 덩어리로 칠하고 주름만 어둡게 넣습니다.
- **모자는 머리카락을 덮는다.** 위에 얹으면 붕 뜨고 아래로 머리가 삐져나옵니다.
  캡모자는 챙을 한쪽으로 빼야 합니다 — 정면 띠로 두르면 경찰 모자가 됩니다.
- **안경 셋은 폭이 같다**(얼굴보다 한 칸씩 넓게). 선글라스만 알을 채우고, 나머지는 알을
  비워 눈이 비칩니다.
- **책상 앞 자세에서는 소품을 그리지 않는다.** 손이 노트북 위라 연필·머그가 허공에 뜹니다.
- **거의 흰 색만으로 물건을 그리지 않는다.** 라이트 카드 위에서 사라집니다(머그는 외곽선).
- **볼(B)은 피부를 붉게, 어둡게가 아니라.** 진한 피부에서 수염 자국처럼 보입니다.

캐릭터 색은 테마와 무관하게 고정이고, **외곽선만** CSS 변수(`--px-outline`)입니다.
어두운 배경에 새까만 외곽선을 쓰면 실루엣 가장자리가 배경에 먹혀 형태가 뭉개집니다.

내보내기는 `src/renderer/src/lib/export.ts`:
- **CSV** — RFC4180 이스케이프, UTF-8 BOM 포함(엑셀 한글 깨짐 방지)
- **클립보드** — 노션/슬랙에 바로 붙는 마크다운 리스트

## 웹사이트로 쓰기 (PWA)

설치 없이 브라우저 주소로 접속해서 쓰는 버전입니다. 데스크탑 앱과 같은 화면·기능(캐릭터, 온보딩, 활동 색 포함)이고, 창 제어(미니 위젯·전역 단축키)만 빠집니다.

```bash
npm run build:web      # → dist-web/ (정적 파일만 나옴)
npm run preview:web    # 빌드 결과를 http://localhost:4173 에서 확인
```

### GitHub Pages 로 배포하기

`.github/workflows/deploy-web.yml` 이 들어 있어서, **main 브랜치에 push 하면 자동으로 빌드 → 배포**됩니다.

1. GitHub 에 저장소를 만들고 이 폴더를 push
2. 저장소 **Settings → Pages → Build and deployment → Source** 를 **GitHub Actions** 로 변경 (처음 한 번만)
3. **Actions** 탭에서 "웹 배포 (GitHub Pages)" 가 초록색이 되면 끝
4. 주소: `https://<깃허브아이디>.github.io/<저장소이름>/`

- 빌드가 `base: './'` 라서 저장소 이름이 뭐든(하위 경로여도) 그대로 동작합니다.
- 워크플로는 배포 전에 타입 검사를 돌립니다. 타입이 깨지면 배포되지 않습니다.
- Electron 실행 파일은 받지 않습니다(`ELECTRON_SKIP_BINARY_DOWNLOAD`). 웹 빌드에는 필요 없습니다.
- Netlify·Vercel·Cloudflare Pages 도 됩니다: 빌드 명령 `npm run build:web`, 출력 폴더 `dist-web`.

### 데이터는 어디에 저장되나

**그 브라우저의 localStorage** 입니다. 서버로 가는 것은 없습니다.

- 다른 기기·다른 브라우저와 공유되지 않습니다. 데스크탑 앱·토스 미니앱과도 따로입니다.
- 브라우저 사이트 데이터를 지우면 기록도 지워집니다. 필요하면 메인 화면의 CSV 내보내기로 백업하세요.
- 시크릿 창에서는 창을 닫으면 사라집니다.

### 오프라인 · 홈 화면 설치

`public/sw.js`(서비스 워커)와 `manifest.webmanifest` 로 한 번 열었던 사이트는 오프라인에서도 열리고, 폰에서는 "홈 화면에 추가"로 앱처럼 쓸 수 있습니다.

- 서비스 워커는 **https(또는 localhost)에서만** 등록됩니다. `dist-web/index.html` 을 파일로 직접 열면 오프라인 기능은 빠지지만 앱은 동작합니다.
- 페이지는 네트워크 우선이라, 새로 배포하면 다음 접속 때 바로 새 버전이 뜹니다.
- 타임라인의 액션 버튼은 `max-sm:opacity-100` 으로 터치 환경에서 항상 보입니다.
- 할 수 없는 것: 앱이 꺼진 상태에서 정시 알림, 알림창 안에서 바로 입력 (`lib/pwa.ts` 머리말 참고).

### 넓은 화면 레이아웃

브라우저 창이 넓으면 왼쪽 열(캐릭터·하루 띠·한 번에 기록)과 오른쪽 타임라인으로 갈립니다. 왼쪽 열이 창보다 길면 **카드가 줄어드는 대신 열이 스크롤**됩니다(`*:shrink-0`). 이게 빠지면 카드가 납작해지고 캐릭터 머리가 잘립니다 — `scripts/check-desktop-layout.js` 가 980·1280·1440 폭에서 지킵니다.
